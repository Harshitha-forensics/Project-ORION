Digital Evidence Review

ORION Investigation Console

Case Reference: ORION-DEMO-001

Investigation objective

Examine available records to understand which archive pages were requested, which files were requested, and what the collected evidence can reliably establish.

Educational Demonstration

Evidence timeline

1 · Search

Research term entered

Example: a visitor searches for “flowers”.

Evidence source: a recorded browser-side event or other relevant record. NGINX does not automatically log text entered into a search box.

2 · Access

Research record requested

Example: Flowers Research Record (ORION-FLOWERS-001).

Evidence source: web-server access log, if available. It may show a request timestamp, path, and response status.

3 · Download request

Evidence package requested

File: Pizza_Evidence_Package.zip

Evidence source: server log entry for the ZIP request. A successful response does not alone prove that the file was completely saved on the visitor’s device.

4 · Local deletion

Device-side evidence required

A local deletion event must be supported by appropriate device or browser artifacts, where available.

GitHub Pages and ordinary web-server logs cannot independently confirm that a visitor deleted a downloaded file.

Evidence correlation

  • Compare timestamps from available sources.
  • Match requested paths to the relevant research records.
  • Use SHA-256 hashes to check file integrity.
  • Document the source and limitations of each finding.

Investigation conclusion

A reliable conclusion is based on corroborating evidence, not assumptions. Separate directly observed events from inferred activity and clearly identify any evidence gaps.

Important: This page illustrates an investigation workflow. Its example events are not live telemetry and must not be presented as actual visitor activity.
